## 3. Today's experiments

Selection always on validation; test scored once.

| Experiment | Result | Decision |
| --- | --- | --- |
| Per-class logit bias on the 5 shop heads (kept only if it helps the held-out half of val products) | test mF1 +1.8 to +3.1 pts on 4 heads; mix no gain | **Installed** |
| Label cleaning on v8 features (drop each class's least convincing training photos; rule chosen on audit half A) | audit half B label-right 84.9% → 87.6%, but archive test 76.1% → 73.7% | **Failed the gate**, nothing exported |
| Garment crop instead of whole photo (OWLv2 box +10% margin), 925 audit photos | label-right: whole 82.8%, crop 76.8%, mean of both 82.8% | **Keep whole photo** |
| Encoder: DINOv2 vs SigLIP 2 (earlier runs, frozen, same test) | DINOv2-B + MLP 54.2% vs SigLIP 2 so400m + MLP 65.8% | Stay on SigLIP 2 |

Notes:
- Label cleaning helps correctly labelled photos but hurts the noisy archive test, which cannot tell "learned better" from "lost real data". A milder rule (drop 10%, three flagger encoders) improved both, but it was not the validation choice; it needs an independent audit before use.
- DINOv3 (Meta, Aug 2025) roughly ties SigLIP 2 in its paper on textures (DTD 87.2 vs 87.7) and fine-grained classification (93.0 vs 93.7); it wins on dense tasks. A frozen bake-off (DINOv3 ViT-L/H+ vs SigLIP 2, ~3–4 GPU h) is proposed, not run. DINOv3 has its own licence (commercial use allowed, with conditions).
- YOLO-style detectors only change speed (OWLv2 takes ~0.9 s of a ~1.5–2.3 s scan): crops do not help the fabric answer. A fast Fashionpedia RT-DETRv2 backend is already coded (`services/vision/detectors/rtdetr.py`) but has never been trained.
- The Kaggle shop-heads run saved v8 features for all 85,737 shop photos in its output (`feats_v8.npy` + paths), so new shop heads no longer need the ~1 h extraction.

## 4. Getting to 0.80–0.85

1. **Human-verified test set.** `runs/human_verify/fabric_label_check.html`: one offline page, 1,151 archive test photos (50 per class; twill 5, vinyl 46; seed 2026). Judges answer Yes / No + the right fabric / Can't tell, never see predictions, and download a CSV. Rules: two people, separately; keep a photo when both say yes (or both say no and pick the same fabric); report Cohen's kappa.
   - One file came back as `label_check_deepseek` (1,151 answers, 29.2% "no", kappa ≈ 0.61 against the earlier audit). Its timing (flat 2.0–9.5 s per photo, "no" as fast as "yes", no pause in 2 h 14 min) looks automated. **It does not count as a human judge unless a person confirms they did it.** A shorter survey (20 per class, ~480 photos) can be built if time is short.
2. **Score v8 on the verified set**, macro F1 first, next to the archive-test number and the reason they differ.
3. **Retrain on cleaned labels** (full LoRA, ~7–13 Kaggle GPU h), selected on clean validation. Estimate, not a measurement: ~84–86% on verified photos.
