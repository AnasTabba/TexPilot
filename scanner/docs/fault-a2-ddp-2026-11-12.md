## Code and preserved behavior

- `training/fault/methods/dinomaly.py` now supports explicit `gpus=2` (default remains one). It spawns two fresh interpreters, initializes standard NCCL DistributedDataParallel with one device per rank, and partitions the **same seeded global minibatch of 16 into 8/8**. It refuses missing GPUs or an indivisible batch rather than silently using one GPU.
- The pinned upstream `global_cosine_hm_percent` computes a top-k threshold over **the entire batch's point distances**. Computing separate rank-local thresholds would change the gradient. New `distributed_cosine_hm_percent` gathers only detached distance maps for the shared global threshold; local image-cosine losses retain upstream hooks/factor and DDP averages the parameter gradients. Clipping occurs after reduction/unscaling. Logged loss is averaged across ranks. FP32 LinearAttention2 protection under AMP, frozen/eval encoder, architecture, StableAdamW hyperparameters, scheduler and hard-mining schedule are preserved.
- `iters=10000` now means **10,000 successful optimizer updates**, with scheduler and mining-step advancement only on successful updates. All ranks synchronize finite-gradient status; overflow halves the scale and retries the same global sampled batch without counting a step. At most 100 skipped updates are tolerated. Attempts/skips and successful steps are retained. Single-device mode uses the same successful-step safeguard; otherwise its RNG behavior is retained.
- Model initialization and NumPy global sample seed remain **2026**. DDP dropout streams are deterministic seeds 2026 and 2027. This preserves seeded reproducibility and stochastic training semantics, **not bitwise equivalence to one-device dropout**. The no-dropout numerical regression establishes gradient/optimizer equivalence; no full-run quality equivalence is claimed.
- Training tiles are written incrementally to a temporary uint8 `.npy` memmap, not stacked/pickled into two giant host copies. Children read the file and materialize only local minibatches. The temporary directory (tiles, rendezvous and intermediate checkpoint) is removed on success/error; private tiles never become retained output artifacts. The launch guard reserves the memmap size plus 6 GiB disk headroom; the method also checks the actual temporary filesystem, which may differ from /kaggle/working, before writing any tiles. Existing conservative host budget covers doubled tile storage and runtime reserve; measured full-DDP RSS remains a GPU-proof/full-run measurement, not an established bound from CPU tests.
- Rank zero writes only the portable trainable state; after both workers exit, the parent rebuilds the same pretrained encoder and restores that state for existing single-device evaluation/scoring. Save/load metadata carries training provenance, without DDP `module.` key leakage. These are portable inference checkpoints, not an implemented mid-run optimizer-resume facility.
- `training/fault/kaggle/full_a2.py` accepts explicit two-GPU execution, checks both visible devices and available memory, reserves memmap/checkpoint disk, records both device properties/world size and final training provenance, and preserves inventory, mask, finite-map, category/result and final-output guards. Existing code/7 jobs use their mounted immutable old source and are unaffected by publishing code/8.

## Upstream import/cwd safety

`methods/_upstream.py` was inspected and left unchanged. Its RLock/module cache and `_chdir` scope are process-global and unsuitable for independently switching repositories in threaded replicas. DDP uses **spawn**, not fork or threaded DataParallel: each child has independent imports, cache, lock and cwd, and wraps its own complete fit in `upstream_repo`. Parent does not hold that context across spawning. It builds its evaluation model only after children exit. No pickling of locally defined attention classes or upstream model objects crosses processes; only primitive configuration, paths and tensor state dictionaries do.
