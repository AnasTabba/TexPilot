# TexPilot stationary incoming-fabric QC design

Status: completed documentation, revised after exactly20 independent Orca reviews, 12 November 2026. Proposed behavior is not shipped behavior. This document and the [implementation plan](../plans/2026-11-12-incoming-fabric-qc.md) supersede broader feature wishlists only for this project scope. Review dispositions live in the [ledger](../reviews/incoming-fabric-qc-2026-11-12/review-ledger.md).

## 1. Decision, scope and research question

One user decision: does this explicitly identified inspected sample conform to the frozen PO construction requirements, or should it be held for review? Phone-assisted **stationary** capture combines a central visible fabric structure/type classifier, localized defect evidence and physically validated construction measurement. Automated statuses are ACCEPT and HOLD only in a validated operating domain; otherwise RECAPTURE or MANUAL_REVIEW. HOLD means sample nonconformance evidence, not reject/pay/dispatch a roll. Neither a clean photograph nor the accepted sample establishes whole-roll acceptance.

Novelty is an experimentally tested risk-versus-automation-coverage system on unseen factory rolls, rather than a claim to invent classification, anomaly detection, FFT or four-point inspection. Compare classifier-only, classifier+defects, classifier+metrology and full gated fusion at matched acceptance risk; report ablations and confidence bounds. Establish whether gating can increase useful coverage without increasing false acceptance under held-out factory/roll/device shifts. A negative result or zero safe automation is a valid research result. Fabric classification remains central; existing fault training continues independently and must not be restarted by this plan.

Excluded: RGB fibre composition or GSM inference, whole-roll certification from samples, automated financial/stock/dispatch actions, ERP expansion, continuous roll tracking by default, speculative inventory integrations, and adoption of a friend's entire feature list. Existing label composition may remain explicitly *stated* legacy evidence; yarn-count estimates are not incoming-QC measurements. A measured GSM from an authorized balance/cutter is external evidence only and is not required in the initial construction domain.

## 3. Authoritative v2 contract (proposed)

All records carry `schema_version: '2'`. IDs are UUIDs; hashes are lowercase SHA256; timestamps UTC RFC3339, finite numeric values only; normalized boxes obey 0<=x0<x1<=1 and 0<=y0<y1<=1. Unknown fields rejected on write; bounded enums and arrays; immutable IDs/version/hash tuples bind evidence. Generate checked JSON fixtures for Python, TypeScript and Swift. Do not introduce a second source of business policy in clients.


Server validates membership and tenant cross-references; workspace_id in responses is derived from session, not trusted from requests. Stage OK denotes completed usable execution, including fabric unknown=true with null authoritative label and diagnostic candidates recorded separately; unknown always forbids automatic decisions. ABSTAINED means no usable inference; FAILED/missing head remain distinct. Stage OK requires non-null schema-valid value and expected artifact; every other state requires null value and reason. Quality check names belong to a pinned domain manifest (`blur`, `glare`, `moire`, `fold`, `framing`, `resolution`, `marker_geometry`), all required true. Exact probability calibration does not turn softmax into a chemical claim. An automatic Decision has automatic=true only for ACCEPT/HOLD; review statuses automatic=false. Audit failure is an HTTP error with no committed Decision, not a fictitious persisted MANUAL_REVIEW. AUDIT_UNAVAILABLE is a client-visible error reason; recovery permits a separately audited review decision after storage restoration.

Error envelope `{schema_version:'2', error:{code:string, reasons:Reason[], retryable:boolean, request_id:string}}`; 401 unauthenticated; 403 role/CSRF/service-auth denial; 404 inaccessible object including foreign tenant; 409 stale version/idempotency-body mismatch/concurrent decision; 413 body/pixel bounds; 415 media type; 422 invalid fields/units/geometry; 429 bounded concurrency; 503 required service/audit unavailable; 504 inference deadline. No internal exception strings or image content in errors. Recoverable image-quality findings return persisted decision status, not 422 syntax error. Server deadline expiry prevents finalization. Client transport failure has unknown outcome until idempotent replay/reload; no cached success fallback.

## 4. Deterministic policy, authority and lifecycle

`evaluate_qc(evidence, spec, policy, release, attempt, context) -> DecisionDraft` is pure, versioned, and independent of learned model code. Defect score thresholds, classifier calibration and domain limits are fitted/validated artifacts; authorized PO tolerances and role rules are policy. Thresholds chosen on calibration data cannot be tuned on release/test data.

Ordered rules: invalid/unconfirmed/stale spec or contradictory provenance -> MANUAL_REVIEW. Missing/failed/disabled required stage, unknown label/OOD, missing release/domain or expired calibration -> MANUAL_REVIEW (capture-fixable quality/scale failure alone may RECAPTURE). For quality-only capture-fixable failures, attempts 1 and 2 -> RECAPTURE; attempt 3 -> MANUAL_REVIEW with RECAPTURE_LIMIT. Attempts count server-allocated capture submissions for the same sample, cannot reset by client retry/new evidence. Mixed capture-fixable and authority/stage failures -> MANUAL_REVIEW. Fully valid evidence in a released domain: confirmed mismatch, defect score at/above released HOLD threshold, or entire density uncertainty interval outside tolerance -> HOLD. Entire uncertainty intervals inside all tolerances, compatible fabric and released low-defect threshold -> ACCEPT. Defect gray zone, density interval crossing tolerance or any ambiguity -> MANUAL_REVIEW. HOLD is also gated, not an automated catchall for unvalidated results. `lower <= upper`, finite nonnegative density and interval endpoints, canonical units and strict taxonomy compatibility are mandatory.

Default policy is REVIEW_ONLY: even apparently conforming evidence returns MANUAL_REVIEW/POLICY_UNRELEASED; use explanatory evidence, no green acceptance badge. Automatic mode requires named factory authority's signed risk tolerance and sampling agreement, physical calibration report, rights/consent clearance, independent release statistics, security and persistence verification. Admin alone cannot fabricate physical/statistical evidence. Operator maps to `quality_inspector` capture/create; supervisor reviews/adjudicates; owner maps to admin approving operating policy/release with named independent QC signatory. Purchase_manager confirms versioned PO facts; sales_manager/dispatch have no QC mutation permission. Admin intervention remains explicit reasoned audit. A reviewer decision appends human adjudication; it cannot rewrite model evidence or turn it into training truth automatically. Human adjudication status is separate from DecisionStatus and never used to auto-run existing ERP flows.

## 5. Provenance, PO and units

PO version freezes normalized construction, allowed taxonomy and axis tolerances with source file/page/span, importer/confirming actor and hash. OCR is a candidate field with confidence, raw span and document hash; a confirmed PO value is authoritative only for what was ordered, never for what was observed. Preserve typed correction/OCR/PO/model/physical fields side by side. Contradictions block automation until a purchase_manager confirms a new immutable version with reason; no silent last-write-wins or OCR override. Concurrent edits use expected version and 409; old samples retain their original spec, recapture under revised spec creates a linked new Sample evaluation (same physical selection), never a differently bound decision on the old Sample and visible stale marker.

Initial domain requires confirmed woven ends/picks or validated knit wales/courses, positive target and explicit absolute lower/upper limits. Canonical count/in uses exact 2.54 conversion from count/cm, dimensions retained; relative tolerance converted once from target and recorded. Do not invent default ±5%, average conflicting units, swap warp/weft based on image rotation, or infer metre/yard roll quantity from kg/tonne. New construction metadata is separate from existing mass inventory units; unsupported units -> review/import error, not new ERP conversions.

## 6. Capture, metrology and operating domain

Stationary flat relaxed swatch on a stable surface, reproducible diffuse lighting and distance, marker coplanar with fabric; image set includes overview for location context and original-resolution close-ups for count/defects. Calibration profile binds camera/lens/resolution/focus/distance range/processing/lighting, validity interval and physical reference IDs. Retain original orientation, EXIF policy, crop/homography and pixel-to-mm Jacobian; validate marker print with a traceable ruler, distortion over image field, residuals and repeatability. EXIF dpi, typed dpi, screen display scale, digital zoom and a printed marker by themselves cannot authorize phone metrology. Lens switching, autofocus drift, perspective, nonplanar fold, unknown marker dimensions or downsampling outside profile -> review/recapture. No reuse of InspectArrival shrink on measurement evidence.

FFT estimates periodic optical signals; assumptions: resolved threads, approximately regular stationary texture, identifiable axis, enough independent repeats and controlled geometry. Nyquist alone and current 2.5px floor are insufficient evidence of accurate counts. Printed checks/stripes, finishing/slubs, aliasing/moire, highlights, doubled harmonics, crossed yarns, knit loops and folds can imitate frequency peaks. Compare FFT with spatial autocorrelation/manual peak evidence and pick-glass count; reject disagreements rather than average. Weave naming from dark crossings is an unvalidated hypothesis. Initial automation can restrict to one physically demonstrated woven class/device combination; knits remain review-only until their own validation.

Measurement intervals include reference-length uncertainty, local distortion, rectification, scale, thread estimator bias, repeat capture, inter-operator and reference-count disagreement; combine with a documented uncertainty budget and measured coverage on unseen rolls (not just tile variance). Proposed development goal: median absolute relative density error <=5% and 95th percentile <=10% against blinded pick-glass consensus, with interval coverage near nominal 95%; these are provisional research targets, not production authority. PO boundary decisions use intervals, never round displayed values. A stricter PO may make automation infeasible despite meeting these goals.

Quality classifiers/heuristics explicitly test blur/motion, saturation/glare, underexposure, fabric fill, scale resolution, moire, folds, patterns, occlusion and marker geometry; thresholds learned per allowed profile and challenged on naturally failed captures. Unknown fabric includes out-of-taxonomy and in-taxonomy low-confidence; OOD detector is fallible and must be tested on unseen materials/domains, not claimed complete. Taxonomy 27 classes mixes weave/style/material marketing labels; establish factory label dictionary, hierarchical aliases and expert disagreement; no mapping denim/twill/knit/jersey into exclusive truths without adjudication. Keep UNKNOWN distinct from missing execution and from defect unknown type.

## 7. Sampling, ground truth and statistics

Unit of automated decision is a uniquely identified inspected sample/location capture set. Record supplier, lot, roll, location, face, planned sampled area, actual usable area and sampling method. Proposed study starts with predeclared randomized locations across independent rolls, including conspicuous failures only as a separately labeled challenge set. No percentage roll coverage unless physical inspected area/roll dimensions are measured; no four-point points/100yd² without inspected area, defect size and authorized scheme. Surface samples do not expose hidden/internal defects. Sampling SOP and lot disposition authority remain factory-QC gates. Contiguous tiles and repeat phone shots from one roll are dependent, never independent sample count.

Two blinded qualified counters independently label fabric and pick-glass ends/picks at registered locations, adjudicate disagreement with retained raw counts and repeatability; qualified defect reference includes overview/location/physical inspection and measured size, not model heatmap truth. Record disagreement/uncertain reference, do not force into clean negatives. Predetermine inclusion/exclusion before unblinding model result; reports include missing and excluded units and their reasons. If factory access absent, use consented lab rolls and clearly call this a lab study, no factory generalization claim.

Define false acceptance primary estimand `P(reference nonconforming | automatic ACCEPT)` on independent held-out units; also report `P(automatic ACCEPT | reference nonconforming)`, prevalence, automatic HOLD precision, review/recapture rates, and coverage `(ACCEPT+HOLD)/eligible submitted samples` plus ACCEPT-only coverage. Report all-submission coverage including invalid captures to avoid denominator gaming. Per-domain fabric macro-F1, per-class precision/recall/F1/confusion and UNKNOWN recall accompany classifier coverage; proposed macro-F1 >=0.85 on factory-held-out known labels is a research target, not evidence. Probability reliability (Brier/ECE plus diagrams) is diagnostic; selective empirical risk and confidence bounds gate release.

Provisional illustration: independent authority might require false acceptance <=1% with one-sided 95% bound. For x failures in n automatically accepted independent units, use exact Clopper–Pearson upper bound `BetaQuantile(0.95; x+1,n-x)` (x=n ->1). Zero failures gives `1-0.05^(1/n)`, requiring n>=299 accepted independent units. At 30% ACCEPT coverage roughly 997 independent submissions before attrition; per-domain testing and multiple comparisons require more. This is not 299 tiles. Conservative initial design selects one predeclared sample per independent roll for confirmatory binomial analysis; correlated-roll observations are descriptive clustered estimates and cluster bootstrap sensitivity, not exact binomial certification. If rolls share a dependent lot/factory process, choose the higher independent grouping or explicitly limit inference. Two factories are not enough to certify unseen factories. Predeclare alpha allocation for domains and primary endpoints, stop rules, fixed audit sample and no repeated unadjusted peeking. Calibration/train/model selection and final release cohorts are disjoint by group/time. Failed release freezes automation until a new independently evaluated version/cohort; do not tune on failures then reuse release cohort. Sparse domains stay review-only.

## 8. Data governance, defect training and reproducibility

Before training create immutable manifest: dataset/source/version/hash/license and permitted purpose, sample/parent/roll/lot/factory IDs, original image and mask hashes, source URLs, label/annotation version and split. Split train/validation/calibration/release-test by highest available group before cropping/augmentation; near-duplicate image perceptual hashes plus manual audit and source provenance connect leakage components across datasets. If roll identity missing, source grouping and conservative dedup are only a limitation, not invented roll independence. Audit ADNet source overlap against MVTec/WFDD/AITEX and all external pretraining/evaluation sources; remove connected groups from test or report benchmark as contaminated/exploratory. Teacher/feature backbone pretraining exposure also disclosed. Unknown benchmark rights mean no redistribution/production promotion pending clearance.

AITEX known defective source with empty mask: **pending user policy**, never silently score normal or repair labels. Dataset owner must resolve against original annotation or predeclare image-level-only/excluded pixel scoring; preserve raw empty mask and report denominator/sensitivity. Until then AITEX results cannot gate release. Other anomalies: missing masks, zero clean masks, shape/orientation mismatches, unions and corrupt files require separate validation cases; empty annotation is not a clean negative by default. Keep raw/derived annotation lineage.

Fabric baseline uses existing training/export pipeline and taxonomy, expert factory labels and macro-F1. Fault comparison reuses ongoing A2 benchmarks and one bounded baseline; do not expand model zoo. [DDP report](../../fault-a2-ddp-2026-11-12.md) records private source v9 and local 66-test proof; real NCCL/T4x2 utilization/throughput proof blocked by two active jobs. This plan performs no Kaggle action. Future training owner verifies completion/quota and collects independent hardware proof before speedup claims; pending AITEX policy remains separate. Pin source commit plus dirty patch hash, upstream SHA, dataset manifests, weights hash, environment lock/container, commands, seed list, hardware/driver, global/per-rank batch, successful/attempted/skipped steps, losses, wall time, peaks and checkpoint hashes. Seeded training with cudnn benchmark is not bitwise reproducible. Validate two-process gradient equivalence, successful update semantics, finite outputs/checkpoint restore and real two-GPU utilization separately. Missing measurements reported unknown. No optimizer-resume claim from inference-only checkpoints.

Consent must cover capture, retention and separately training/research use; opt-out cannot prevent ordinary manual QC. Minimize faces/labels/business secrets; strip GPS from derived artifacts and protect originals; encrypt transport/storage and workspace-scoped access, no raw images in logs. Proposed retention default: local draft expires after 24h, uploaded research originals after 30 days, QC audit metadata 180 days, subject to signed factory/legal agreement before collection; freeze/purge workflows and backup expiry must be specified. No collection starts on provisional retention alone. Rights/consent registry and dataset deletion/tombstones propagate to training exclusion and future models; explain that already trained artifacts may need withdrawal/retraining depending agreement. Active learning samples both abstentions and random accepted/held samples with logged probabilities; no training on selected disagreement only or unadjudicated model labels. Keep new annotations out of sealed test; promotion requires complete bundle including taxonomy, calibration, policy, preprocessing and domain manifest, independent QC reviewer signature and rollback predecessor.

## 9. Persistence, auth, concurrency and compatibility

Worker session and CSRF/origin verification precede v2 parsing/forwarding. Backend accepts short-lived audience-bound service assertions carrying derived workspace/user/request and payload hash; deployment's private proxy credential protocol must be reconciled in integration test (existing bearer helper is not assumed to match provider auth). Scanner rejects missing/expired/wrong audience assertion and direct public v2 calls. CORS is not authentication. Use fixed HTTPS upstream allowlist, refuse redirects, cap bytes/pixels/decode time, MIME magic, finite numbers and path traversal; rate-limit PIN/login and captures per actor/workspace plus global inference capacity. Do not expose configurable arbitrary server URLs to production operators. Four-digit PIN shared-device threat requires factory security signoff and reauthentication for promotion; migrate auth if rejected, no security claim from salted SHA256 alone.

Proposed authoritative D1/local tables: `qc_po_specs`, `qc_samples`, `qc_captures`, `qc_evidence`, `qc_decisions`, `qc_adjudications`, `qc_releases`, `qc_idempotency`, append-only `qc_decision_events`; all tenant rows include workspace_id and composite foreign keys. Blob IDs/hashes in metadata only; object storage adapter follows existing bucket/local pattern. Immutable specs/evidence, versioned decision revisions and optimistic expected_revision; one current decision pointer guarded by transaction, no destructive overwrite. Idempotency keyed `(workspace_id, actor_id, route, client_key)` with canonical body hash and durable response; same request concurrent returns same record, different hash 409, crash after commit replays. Client cannot set automatic/release/model fields. Audit and decision commit atomically; stage originals as pending, verify checksum, commit references, then finalize; orphan garbage collection after grace, never delete live references. Inference failure leaves observable request state and retryable job with same ID, not partial ACCEPT. Keep CPU inference outside DB transaction; finalization rechecks spec/release/capture hashes and expected revision atomically.

Expand-only migration after verified restorable backup: add tables/indexes/constraints and schema version, deploy backend supporting v1/v2, then web/native v2; legacy scan/spec and inspection routes remain unchanged. New QC automation stays off during mixed versions. No migration of old PASS to new ACCEPT, no conversion of existing inventory quantities, no destructive contraction in this plan. Test empty and populated databases, interrupted/replayed migrations in actual SQLite and D1 adapter, and old/new readers. Roll back application to previous release with additive tables preserved and automation kill switch; restore snapshot only as supervised disaster recovery with incident cutoff and replay/reconcile audit, since blind restore loses later writes. Recovery owner must demonstrate object/DB consistent point recovery and reconcile orphan/incomplete rows before pilot.

## 10. Web, native, accessibility and partial failure

New incoming sample workflow: select existing PO/version, identify roll/location, display scope and confirmed requirements, capture guided overview/detail/marker, show quality fixes, analyze, show fabric answer/unknown, defect overlay, measurement interval/reference and final sample status with reason, then record optional human review. No default accepted quantity or call to existing arrival submit. Preserve original high-resolution file for metrology, bounded preview separately. Cancel stale requests via AbortController but still ignore late results unless sample/spec/capture hash/revision matches. Clear previous green result immediately on any edit; reload revalidates release/spec server-side. Revoke blob URLs and cap draft storage.

Offline is draft-only, not inference or decision: encrypted/OS-protected local capture queue where platform supports it; otherwise explicit memory-only draft with warning. Stable request/capture IDs survive retry; backoff 1,2,4 seconds then explicit retry for retryable transport/429/503 only, Retry-After respected up to 60 seconds; never retry 401/403/409/422 blindly. Expired session reauth before upload; logout/account/workspace change purges accessible drafts and caches; privacy requires no sensitive API/image service-worker caching. Duplicate upload/reconnect resumes checksummed chunks only if designed/tested; initial small bounded single uploads may restart with same idempotency ID.
