# Reviewer 09 — leakage, licenses, privacy and consent

Recommendation: **revise before implementation involving real captures or new training/export**. No P0 found. The design correctly identifies G4 as an external data-steward/factory-legal gate, forbids collection on provisional retention, separates training consent from ordinary QC, and requires grouped leakage auditing; the gaps below are missing executable ownership/proof, not evidence that proposed v2 already ships. Review-only mode does not waive privacy or rights gates.

## Findings

### P1 — Existing training export asserts CC0 for mixed artifacts; planned rights audit does not guard this actual exit

**Evidence:** `scanner/training/textilenet/retrain_rounds_stage.sh:16-25` copies serving/training source, feature caches, the prelim split and installed model weights into one Kaggle dataset and declares the entire dataset `CC0-1.0`; lines 30-37 upload/version it and push a kernel without a rights check. `scanner/training/fault/publish_code.sh:30-56` likewise stages essentially all small files under training/services and labels rights merely `other`. Neither declaration proves permission. Design §7 (`2026-11-12-incoming-fabric-qc-design.md:133,139,183`) promises source/weight rights clearance; plan T09/T10 (`2026-11-12-incoming-fabric-qc.md:144-162`) owns manifests/evaluation but neither names these exporters nor asserts export permission. The existing private kernel flag is not a grant of source, feature or weight redistribution rights.

**Correction:** Inventory these actual exporters as legacy paths requiring clearance before reuse; bind the staged file list/hashes to per-artifact licenses, upstream notices, permitted destinations and purposes. Reject unknown or incompatible export permissions before any upload and remove the blanket CC0 claim unless supported for every included artifact. Do not infer licensing from robots access: the shop scraper (`scanner/training/textilenet/shop_scrape.py:98-124,156-178`) records URLs/products and downloads images but records no permission/license. Actual interpretation and permission remain G4 authority decisions; this review does not conclude any particular upstream license is violated.

**Test assertion:** With fake Kaggle transport, one unknown-rights feature/weight/source file causes zero dataset/kernel calls; permitted research training with forbidden redistribution still fails export; the staged manifest preserves required notices and cannot silently label the bundle CC0.

### P1 — Consent is a string in Capture, with no owned registry or pre-upload enforcement contract

**Evidence:** Design Capture has `consent_record_id:string` (`design:67-70`), but proposed tables (`design:145`) omit a consent/rights registry and the endpoint map (`plan:40`) has no registry workflow. T02/T05 assertions (`plan:60-66,96-102`) test tenancy/auth but not consent scope, expiry or withdrawal. T09 (`plan:144-150`) calls consent an explicit G4 gate but starts separately from the T01–T07 Nov29 capture path (`plan:44`); its prohibition is not wired into capture writes. Actual legacy scan persists original uploads without consent metadata (`scanner/services/api/main.py:98-100`; `store.py:17-25,44-62`), so reusing that mechanism cannot supply the missing check. This is a proposed-contract gap, not a claim v2 currently collects unlawfully.

**Correction:** Assign T01/T02/T05 a minimal server-owned, versioned consent/authority record or verified external-register reference, with workspace, subject/factory authorization, capture/operational retention scope, separate research/training scope, expiry/withdrawal and signed authority evidence. Check capture permission before accepting/staging bytes, and research/training eligibility again at export/use. Make initial consent clearance an explicit dependency of the demo capture path; refusal of research use must preserve ordinary manual QC.

**Test assertion:** A syntactically valid but unknown, foreign-workspace, expired, withdrawn or research-only consent ID cannot create a capture/blob; operational-only consent permits authorized QC but excludes research export/training; changing mode to REVIEW_ONLY does not bypass consent. Signed permission and legal adequacy require G4 evidence, not a passing mock test.

### P1 — Retention/deletion promises have no implementation owner and conflict with permanent live references

**Evidence:** Design `:139` requires 30-day research-original expiry, tombstones/training exclusion and backup expiry; `:145` requires immutable evidence and says orphan GC must never delete live references. The plan matrix (`:212`) promises a deletion/backup-expiry drill under T09/T12, but T09 only creates manifest/audit and register/SOP files (`:144-150`); T12's named assertions (`:180-186`) exercise restore/reconciliation, not deletion, expiry, holds or withdrawal. There is no specified way to expire a referenced original while retaining an honest audit. Existing `scanner/services/api/store.py:44-63` writes raw original bytes indefinitely, and `scanner/deployment/modal_scanner.py:14,50,73` mounts a persistent scan volume; a new QC bucket purge would not cover this legacy copy if accidentally reused.

**Correction:** Assign a concrete lifecycle procedure/implementation and test to the storage owner before collection: distinguish operational evidence from research copies; define retention start, authorized hold/release, protected original access, tombstoned/unavailable evidence representation, derived caches/features/exports and backup expiry. Explicitly prohibit v2 diagnostic-store writes and specify restore-time tombstone reconciliation before restored data becomes accessible or eligible for training. G4 must approve retention and treatment of already trained artifacts; do not promise automatic model unlearning.

**Test assertion:** Advance an injected clock through the signed retention period: expired blobs and derived research copies are inaccessible, retained audit reports evidence purged rather than claiming reproducibility from missing bytes, held evidence remains only under authorized hold, training manifests reject tombstoned IDs, and restoring an older backup cannot resurrect withdrawn data. Spy on legacy ScanStore during v2 analysis and assert zero writes.

### P2 — Grouped split audit is specified, but the actual training entry-point bridge can bypass it

**Evidence:** Design `:133` requires split groups before augmentation and disclosure/audit of backbone pretraining exposure; T09 tests group/overlap rules (`plan:148`). Existing `scanner/training/textilenet/splits.py:64-70,89-119` stores only path/label/split/source/SHA1 and randomly carves validation by image after byte-identical dedup; this cannot enforce parent/product/roll or near-duplicate groups. The existing retraining exporter explicitly copies `data/splits/prelim/fabric.csv` and cached features (`retrain_rounds_stage.sh:21-23`). T10 says extend existing adapters, but its assertions (`plan:160`) require reproducibility metadata rather than requiring those adapters to consume the audited sealed manifest and rejecting legacy split substitution. A good standalone audit does not demonstrate that the fitted artifact used its output.

**Correction:** Require the QC training/evaluation wrapper to consume only a successful sealed audit hash and bind image/feature membership, group, split and backbone provenance to the fitted bundle. Legacy benchmark reproduction can retain its existing official split if labeled exploratory; it must not supply confirmatory QC release evidence. Unknown historical pretraining exposure must remain disclosed uncertainty, not an invented clean audit.

**Test assertion:** Supply a clean audited manifest but a cached feature/prelim CSV containing an extra release group or same-product image in training: fitting/evaluation fails before model execution. Changing any manifest or feature membership invalidates the audit binding; unknown pretraining provenance cannot be reported as verified unseen exposure.

## Inspected paths and proof limits

Read the complete target design and implementation plan, with focused line checks of their contracts, dependencies, rights/retention passages and T01–T13 assertions. Inspected actual source: `scanner/services/api/{main,store,config}.py`, `scanner/deployment/modal_scanner.py`, `scanner/training/textilenet/{splits.py,shop_scrape.py,retrain_rounds_stage.sh,retrain_rounds_kernel-metadata.json}`, `scanner/training/fault/publish_code.sh`, fault data/method source references, and `yarnflow/server/scanner-proxy.mjs`. Repository filename search found no scanner license file; that absence is not proof that downloaded datasets or models have no licenses. Source review only: no product changes, installs, training, external uploads, GPU/Kaggle calls or legal clearance performed.

Final recommendation: retain the existing fail-closed G4 language, but give consent enforcement, artifact export permission and lifecycle deletion explicit pre-collection owners/contracts/tests; bind actual training adapters to audited manifests before accepting release evidence. Named external authorities must supply permissions and signed retention decisions; local tests prove enforcement only.
